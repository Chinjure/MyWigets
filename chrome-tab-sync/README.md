# chrome-tab-sync — DesktopTopBar Chrome 标签同步扩展

把 Chrome / Edge 当前聚焦窗口的**真实标签页**实时同步到 DesktopTopBar 桌面顶栏，
顶栏可直接操作这些标签：点击切换、中键关闭、右键新建、按住拖动重排。

## 安装（一次即可）

1. 打开 Chrome / Edge，地址栏进入 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**，选择本目录 `chrome-tab-sync`
4. 完成。浏览器重启后扩展自动随浏览器启动并重连顶栏

> 无需注册表、无需浏览器启动参数、无需重启电脑。
> **修改本目录代码后，需在扩展页点「重新加载」才会生效**（或重启浏览器）。

## 使用

| 操作 | 效果 |
| --- | --- |
| 聚焦任意 Chrome/Edge 窗口 | 顶栏标签变为该窗口内的真实标签页（标题实时同步） |
| 左键点击标签 | 切换到该标签页（并聚焦对应浏览器窗口） |
| 按住标签左右拖动 | 重排标签顺序（顶栏实时让位，松手后浏览器里的真实顺序一起变） |
| 鼠标中键点击标签 | 关闭该标签页 |
| 右键标签 | 新建标签页 |
| 关闭浏览器 / 卸载扩展 | 顶栏自动回退为原来的「窗口枚举」模式 |

多窗口场景：顶栏始终显示**当前聚焦**的浏览器窗口的标签；
通过顶栏切换到另一窗口的标签时，同步目标自动跟随。

拖动重排的细节：拖动中被拖标签浮在光标处、其余标签实时补位，原位置留空处
即落点；松手时顶栏把新位置作为 `moveTab` 下发给扩展，扩展执行
`chrome.tabs.move` 后浏览器会推 `tabMoved` 回来对齐。固定标签（pinned）
永远排在窗口最前：普通标签拖不进固定区，固定标签也拖不出固定区。

> 顶栏更新后**首次**使用拖动重排，需要到扩展页点「重新加载」——
> 新命令 `moveTab` 是本次新增的扩展侧处理（见 background.js）。
> 未重载时顶栏仍会立刻显示新顺序，但浏览器里的标签不会跟着动。

## 工作原理

```
浏览器扩展（chrome.tabs API）
   │  WebSocket ws://127.0.0.1:9786
   ▼
DesktopTopBar 内置 WS 服务端（顶栏进程内，仅绑定本机回环地址）
   │  事件推送：hello / windowFocused / tabCreated|Updated|Removed|Moved|Activated
   │  命令下发：activateTab / closeTab / newTab / moveTab（拖动重排）
   │  应用层心跳：ping / pong（15s，保活 MV3 Service Worker）
   ▼
顶栏标签区渲染（Chrome 风格，含激活高亮 / 固定标签圆点）
```

- 扩展只向顶栏推送**当前聚焦浏览器窗口**的标签（`tabs` + `alarms` 权限，
  无需任何网站权限）
- 顶栏内置的 WS 服务端只监听 `127.0.0.1:9786`，不对外网开放

## 为什么必须做应用层心跳（重要）

MV3 的 Service Worker **空闲约 30s 就会被浏览器回收**，SW 持有的 WebSocket
会被一起关闭。这**与系统省电模式、Edge 的「睡眠标签页」无关**，是 MV3 的
固有行为——所以"关掉省电模式"并不能解决问题。

关键点（Chrome/Edge 116+）：

- 只有 **JS 收到一条 WebSocket 消息**，才会重置这 30s 的回收计时器；
- WS 协议层的 ping/pong 帧由浏览器网络栈直接应答，**不会派发到 JS**，
  对保活无效。

因此本方案让两侧互发**应用层 JSON 心跳**（`{"type":"ping"}` / `{"type":"pong"}`，
15s 一次，30s 阈值的 2 倍余量）：

- 顶栏空闲 15s 就推一条 JSON `ping`（文本帧，走 JS）；扩展收到后回 `pong`；
- 扩展侧每 15s 也主动发一条 `ping`，顶栏回 `pong`；
- 只要顶栏在运行，SW 就常驻、连接就不断（这是"实时同步"的前提）；
- `chrome.alarms`（0.5min，浏览器允许的最小周期）仅作为 SW 真被回收后的
  **复活兜底**。

顶栏侧另有一层容错：扩展短暂掉线时**保留最后一批浏览器标签 4s**（优雅期），
期间重连成功就无缝续上；只有优雅期结束仍未重连才清空并回退为窗口枚举。

### 症状与根因（历史 bug）

现象：顶栏只剩当前标签页，其他标签页消失。

根因：SW 被回收 → WebSocket 断开 → 顶栏清空同步数据、回退成"枚举浏览器顶层
窗口"。当只开了一个浏览器窗口时，窗口枚举就只有一条（标题取自当前标签），
看起来正是"只剩当前标签页"。旧版扩展的保活间隔是 60s（远大于 30s 回收阈值），
于是连接大约只有一半时间在线。

## 文件

- `manifest.json` — MV3 清单（权限：`tabs`、`alarms`）
- `background.js` — 后台服务：WS 桥 + tabs/windows 事件监听 + 命令处理 + 心跳保活

## 故障排查

- **顶栏没显示浏览器标签**：确认扩展已加载（扩展页中无报错），且顶栏进程在
  运行；检查端口是否被占用：`netstat -ano | findstr :9786`
  （占用者应是 `MyWigets-x64.exe`）。
- **改了 background.js 不生效**：到扩展页点「重新加载」。
- **标签不更新**：刷新扩展页即可重连；或重启顶栏（运行部署脚本 / 重新启动
  `MyWigets-x64.exe`）。
- **想确认连接是否稳定**：`netstat -ano | findstr :9786` 应长期保持一条
  `ESTABLISHED`（若每 30s 出现一次断开-重连，说明保活失效）。
- **不想用扩展时**：在扩展页停用即可，顶栏自动回到原模式。
